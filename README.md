# agentic-job

> This text was generated by an LLM ([how cgwalters uses LLMs](https://github.com/cgwalters/cgwalters#llms)). cgwalters has not reviewed it yet.

agentic-job makes a CI job safe for untrusted steps, then runs
a coding agent as one of them.

## Core features

- **ACP-driven agents.** `run` drives Claude Code (through
  `claude-agent-acp`), opencode or Mistral Vibe over the
  [Agent Client Protocol](https://agentclientprotocol.com): one session
  transport, a redacted transcript, and the session rendered in the run
  summary ([harness](docs/harness.md)). With `acp-drive`, off unless
  configured, the agent can drive a second Vibe agent turn by turn
  ([a second agent](docs/harness.md#a-second-agent)).
- **Safe outputs.** The agent doesn't have a write token. It leaves requests in
  gh-aw's format ("open a pull request with this patch", "comment on this
  issue"); `check` validates them on a machine the agent never touched,
  against the repository's allow list. Only then does `apply` carry them
  out in a separate job ([safe outputs](docs/safe-outputs.md),
  [workflow](docs/workflow.md)).
- **Brokered inference.** The reusable workflow doesn't put a model key in the
  job. The agent reaches the model through a credential broker on another
  machine with a token for one run, and `run` caps its requests and
  reported cost ([inference](docs/inference.md)).
- **secure-host.** One setup step takes root away from the later steps
  of any job, agent or not, and probes to confirm it worked
  ([secure-host](docs/secure-host.md)).
- **Event triggers.** A comment command, label, pull request or schedule
  can start a run; the workflow decides who may trigger it before
  anything untrusted runs, and hands the agent the event's text as data
  ([events](docs/events.md)).
- **Interactive sessions**, partly built: a session run takes an
  operator's prompts after its task's turn, through a bridge on the
  runner's tailnet ([interactive](docs/interactive.md)).

Hardening doesn't need an agent; everything that needs root runs before it:

```yaml
jobs:
  build:
    runs-on: ubuntu-26.04
    steps:
      - run: sudo apt-get install -y libfoo-dev   # root: before the step
      - uses: actions/checkout@v7
      - uses: cgwalters-forge/actions/secure-host@COMMIT
      - run: make check                           # runner's user, no sudo
```

Losing root does not hide the job's tokens from later steps. The reusable
workflow keeps write credentials in separate jobs
([token boundaries](docs/workflow.md#which-tokens-reach-what)).

**Agent security is just CI security.** An agent is code you did not
write, steered by text you did not write, like a build script from a pull
request: take root away from it, don't give its job a token it could
misuse, and check its output on another machine before a write token acts
on it ([trust](docs/requirements.md#actors-and-trust),
[tokens](docs/workflow.md#which-tokens-reach-what)). For most people
[gh-aw](https://github.com/github/gh-aw) is the right choice today; this
runs the agent as a host user, not in a container
([why](docs/background-ghaw.md#why-a-host-user-and-not-a-container),
[related projects](docs/related-projects.md)).

## Try it

This caller runs the scripted agent, which doesn't need a model or a broker.
It tries the things it must not be able to do, changes one file, and the
change comes back as a draft pull request from the bot account's fork.
[`example.yml`](.github/workflows/example.yml) shows how this repository
runs the same caller.

`.github/workflows/agent.yml`, in a public repository of your own:

```yaml
name: agent
on:
  workflow_dispatch:
    inputs:
      task: { type: string, required: true }
permissions: {}
concurrency:
  group: agent-${{ github.workflow }}
jobs:
  run:
    # A full commit you have read, or a version tag (see below).
    uses: cgwalters-forge/agentic-job/.github/workflows/agentic-job.yml@COMMIT
    permissions:
      contents: read
      issues: read
      pull-requests: read
      actions: read
      id-token: write
    secrets:
      SAFE_OUTPUTS_PAT: ${{ secrets.SAFE_OUTPUTS_PAT }}
    with:
      id: ${{ github.run_id }}
      task: ${{ inputs.task }}
      repo: ${{ github.repository }}
      outputs: create_pull_request,noop
      allow: .github/agentic-job/allow.toml
      # The hardening for hosted ubuntu-26.04, read from agentic-job at
      # COMMIT: no copy to keep, and the pin covers it.
      config: .agentic-job-source/.github/agentic-job/hosted.toml
      apply-environment: agent-apply
      agent: fake
      # Nothing counts model requests without a broker, and a cap that
      # nothing counts is refused.
      max-requests: "0"
```

`.github/agentic-job/allow.toml`, with your repository in `repos` and
your default branch in `bases`. If that branch is not `main`, also set
`base: YOUR_DEFAULT_BRANCH` in the caller's `with:` block: the workflow
defaults to `main`, not the repository's default branch.

```toml
hosts = ["github.com"]
repos = ["OWNER/REPO"]
bases = ["main"]
max_outputs = 3
max_patch_bytes = 1048576
max_patch_files = 50

[github.outputs]
create_pull_request = { max = 1 }
noop = { max = 1 }
missing_tool = { max = 1 }
```

It also needs these standard settings:

- **Accounts.** Yours, owning the repository, and a dedicated bot account
  that does not own it, does not belong to any organization and has write
  access only to its own forks.
- **Secret.** `SAFE_OUTPUTS_PAT`: a classic PAT of the bot account with
  the `repo` and `workflow` scopes, stored in an environment named
  `agent-apply` that is limited to your default branch
  ([pull requests come from a fork](docs/workflow.md#pull-requests-come-from-a-fork)).
  An empty secret, or your own PAT (unless the repository
  [accepts that](docs/workflow.md#a-repository-the-applying-account-owns)),
  fails in apply after the agent has run; `require-safe-outputs-pat: true`
  refuses both before it.
- **Settings.** Actions enabled, and `cgwalters-forge/agentic-job` and the
  actions it pins allowed if the repository restricts actions. The pull
  request's CI runs as an outside contributor's would.

Commit both files to your default branch and start it:

```sh
gh workflow run agent.yml -f task='say hello'
```

`COMMIT` may also be a release tag such as `v0.6.4`, which does not include
later changes on main; binaries are prebuilt and attested, or built in the
run ([versions and binaries](docs/workflow.md#things-a-caller-should-know)).

**A real agent** needs a credential broker
([what a broker provides](docs/inference.md#what-a-broker-provides)), but
it doesn't need any secret beyond `SAFE_OUTPUTS_PAT`. Replace
`agent: fake` with `claude`, drop `max-requests: "0"` (the default caps at 150 requests, which the
broker counts), and pass `inference-url` and `inference-audience` from the
broker's operator and an `agent-runner` that reaches the broker;
agentic-job doesn't provision runners. The
[real agent checklist](docs/workflow.md#real-agent-checklist) has the rest.

## What is real today

The binary is written in Rust. The workflow, the sandbox and the checks run
end to end on same-repository pull requests here, with the scripted agent,
on GitHub's hosted Ubuntu 26.04 runners. Claude Code and opencode have each
run real tasks on it on RHEL 10 runners. Cross-repository trials opened
pull requests before apply switched to forks
([#59](https://github.com/cgwalters-forge/agentic-job/issues/59)). The fork
path has run live once, from `cgwalters-forge/tracker`; the caller in
[Try it](#try-it), from a fresh repository, has not
([deployment evidence](docs/workflow.md#what-has-run-and-what-has-not)).

For hosted runners reaching a private broker, the current deployment is
this repository's review gate with opencode on `ubuntu-26.04`
([run 38666714558](https://github.com/cgwalters-forge/agentic-job/actions/runs/38666714558)).
It joins the network in a caller-owned step in the
[composed form](docs/workflow.md#the-pieces-and-an-agent-job-of-your-own).
Older callers must [migrate from the removed Tailscale inputs](docs/workflow.md#migrating-from-the-tailscale-inputs).

Not supported: most of gh-aw's catalogue. Private targets are refused unless the caller
opts its own repository in under the conditions of
[private repositories](docs/private-repositories.md).
Pull requests from forks
do not get the end-to-end jobs that write. The sandbox setup takes two
to five minutes on a hosted runner. Only its authors have used it.

## Known gaps

This behaviour does not match what a new user would expect. Each item links
to the issue that tracks it, where one is filed, or to the page that explains it.

- Steps after `secure-host` lose root but keep the job's tokens and an open
  network ([one trust level for the rest of the job](https://github.com/cgwalters-forge/actions/blob/main/secure-host/docs/threat-model.md#one-trust-level-for-the-rest-of-the-job)).
  No agent job has `id-token`: a register job before it registers the run
  ([the run token](docs/workflow.md#the-run-token)).
- The egress proxy lets any host be read unless its policy file sets
  `[egress] mode = "allowlist"`, which is off by default
  ([the agent's network](docs/sandbox.md#what-setup-does-for-an-agent)).
- The agent is the runner's user, the only agent user since the sandbox
  user was removed ([#2989](https://github.com/cgwalters-forge/agentic-job/issues/2989)):
  it can read whatever the job holds, and `run` refuses a private target.
- `sandbox.close-resolved`, off by default and set by `hosted.toml`, closes
  systemd-resolved's Varlink socket to every user but root. Every later
  step and the agent run as the runner's user, which still resolves names,
  so data can leave through DNS
  ([not claimed](https://github.com/cgwalters-forge/actions/blob/main/secure-host/docs/threat-model.md#not-claimed)).
- The world-write policy is proven at run time on hosted Ubuntu 26.04
  ([CI's controls](https://github.com/cgwalters-forge/actions/blob/main/secure-host/docs/evidence.md#run-time-controls-through-the-action-on-hosted-ubuntu-2604)),
  not on RHEL 10. The image admits RHEL 10, but no run has tested the policy there yet
  ([RHEL 10](https://github.com/cgwalters-forge/actions/blob/main/secure-host/docs/evidence.md#rhel-10)).
- The reusable workflow doesn't accept a model key or an MCP credential, so
  a real agent needs a broker. This stays so until the runner's processes
  are kept from reading `run`'s environment and memory ([#1618](https://github.com/cgwalters-forge/agentic-job/issues/1618);
  [refused for now](docs/inference.md#a-provider-api-key)).
  Where an agent job of your own uses a key, nothing outside the provider
  caps what it spends.
- A broker admits a caller's own agent job by repository, allowing any
  workflow in it ([tracker#452](https://github.com/cgwalters-forge/tracker/issues/452)).
- A missing, empty or owner's `SAFE_OUTPUTS_PAT` fails only in apply,
  after the agent has run, unless the call sets `require-safe-outputs-pat`
  ([checking the token first](docs/workflow.md#checking-the-token-before-the-agent)).
- Pushing to a stale fork with a PAT that lacks the `workflow` scope has
  not been tried ([#426](https://github.com/cgwalters-forge/agentic-job/issues/426)).
- Setup takes minutes ([#188](https://github.com/cgwalters-forge/agentic-job/issues/188)).
